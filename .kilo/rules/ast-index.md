# Поиск кода через ast-index

Для поиска определений, символов, использований, реализаций и структуры проекта сначала запускай ast-index через терминал из корня соответствующего проекта.

При любом запросе на исследование или поиск кода, включая «найди авторизацию», «где реализовано» и «какие функции вызывают», прежде чем вызывать Grep, Glob или встроенный поиск:
1. Выполни `ast-index stats` из корня проекта.
2. Если индекс отсутствует, выполни `ast-index rebuild` и дождись завершения.
3. Если запрос содержит имя переменной, константы, функции или класса, сначала выполни `ast-index symbol "Имя"`; если нужное определение не найдено, выполни `ast-index search "Имя"`. Этот порядок обязателен, даже если пользователь передал полную строку кода, объявление константы или регулярное выражение с именем символа. Например, для строки `const NUMERIC_FIELDS = [...]` сначала ищи символ `NUMERIC_FIELDS` через индекс.
   Для остальных запросов выполни структурный поиск через `ast-index search` по подходящим словам. Для авторизации начни с `auth`, `login`, `session`.
4. Для найденных символов используй `usages`, `callers` и `outline` по необходимости.

На этом Mac бинарник доступен по пути `/opt/homebrew/bin/ast-index`. Если терминал Kilo не находит `ast-index` в PATH, используй этот полный путь.

Команды:
- `ast-index search "запрос"` — общий поиск.
- `ast-index symbol "Имя"` — определения символа.
- `ast-index usages "Имя"` — использования.
- `ast-index implementations "Имя"` — реализации.
- `ast-index callers "ИмяФункции"` — места вызова.
- `ast-index outline путь/к/файлу` — структура файла.

Не заменяй эти команды обычным текстовым поиском. Если ast-index вернул подходящие результаты, не повторяй тот же поиск через grep, rg или встроенный поиск.

Обычный текстовый поиск допустим для строк, комментариев, регулярных выражений или если ast-index ничего не нашёл, но только после указанных выше проверки индекса и структурного поиска. Не обходи этот порядок, превращая запрос на исследование кода в поиск регулярным выражением.

Если нужно проверить точный текст после поиска символа, сначала прочитай соответствующий участок найденного файла. Grep/rg допустимы после поиска через индекс, если нужный результат не найден или точный текст невозможно проверить по найденным участкам.

Не делай вывод о покрытии языков и каталогов индексом только по типу проекта или количеству проиндексированных файлов. Не считай JavaScript или другой язык отсутствующим в индексе без проверки. Если предполагаешь неполное покрытие, сначала проверь индекс поиском нужного символа и файла через `ast-index symbol`, `ast-index search` или `ast-index file`; отсутствие результата опиши как результат проверки, а не как доказательство отсутствия поддержки языка.

Если индекс отсутствует, запусти `ast-index rebuild` из корня проекта. После изменений кода и переключения ветки запускай `ast-index update` перед следующим поиском.

Если команда недоступна или завершилась ошибкой, сообщи об этом и используй доступный текстовый поиск.
