### planner
Агент planner определён пока только в задании (файл .kilo/agent/planner.md ещё не создан — в .kilo/ файлов нет; в docs/setup/agents.md заголовок # planner пуст). По формулировке из задания его возможности такие:

Что делает
Строит план изменений до написания кода. Читает код, AGENTS.md и docs/setup/code_map.md, а результат пишет в docs/plan/. План всегда содержит 4 раздела: Файлы, Шаги, Тесты, Риски.

Права (из frontmatter)
Действие	Разрешение
Чтение	всё (ограничений в его блоке нет; .env* закрыт общими правилами AGENTS.md)
Редактирование	только docs/plan/** — всё остальное ("*": deny) запрещено
Bash	полностью запрещён — не может запустить make test, git, php -l, ничего
Ключевые ограничения (из инструкции)
Код не меняет никогда — даже при явной просьбе в постановке задачи, потому что edit везде закрыт, кроме docs/plan/.
Не додумывает недостающие данные — если входной информации мало, перечисляет, чего не хватает, вместо того чтобы изобрести решение. Это особенно важно для проекта: пороги из backend/config/rules.php трогать нельзя (правило AGENTS.md про риск-менеджмент), и планировщик должен остановиться и зафиксировать вопрос, а не предложить менять порог.
Практический смысл
Такое разделение труда даёт конвейер: scout (только читает/ищет — уже отработал на пробеге) → planner (пишет plan_<ID>.md в docs/plan/, код не трогает) → основной агент/кодер (реализует план). Планировщик физически не может «заодно поправить код», потому что права режутся на уровне конфига, а не обещаниями в тексте инструкции.

### scout
`scout` — встроенный в Kilo агент-разведчик (доступен как тип subagent в Task, вызывается вручную через `@scout`). В `docs/setup/agents.md` он описан одной строкой: **«только читает и ищет по коду»**.

## Что делает
- Исследует кодовую базу: ищет файлы по паттернам (glob), ищет по содержимому (grep), читает файлы.
- Отвечает на вопросы вида «где читается X», «как устроен модуль Y», «кто использует функцию Z» — как в примере выше с поиском всех чтений пробега: он вернул список файлов со строками и группировкой по слоям.

## Чего не делает
- **Не пишет и не редактирует файлы** — только чтение и поиск. Никаких правок кода, никаких артефактов в `docs/`.
- Не выполняет меняющих операций (коммитов, сборок, тестов с изменениями).
- Не принимает решений о реализации — его результат это факты о коде, а не план.

## Отличие от planner
| | scout | planner |
|---|---|---|
| Тип | встроенный агент Kilo | свой агент (пишется руками в `.kilo/agent/`) |
| Результат | устный отчёт (файлы, строки, выводы) | файл `plan_<ID>.md` в `docs/plan/` |
| Права | только чтение | чтение всего + запись в `docs/plan/**` |
| Роль | сбор фактов до/во время работы | построение плана изменений до кода |

Получается конвейер: **scout** собирает факты (где что находится) → **planner** превращает их в план с разделами Файлы/Шаги/Тесты/Риски → кодер реализует. Scout при этом безопасен по построению: он физически не может ничего сломать, потому что у него нет прав на запись.
