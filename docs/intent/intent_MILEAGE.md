# Intent: пробег авто не больше 400 000 км, иначе решение review (MILEAGE)

## Замысел

В расчёт решения по заявке добавить проверку пробега: пробег не больше
400 000 км — решение считается как сейчас; пробег выше — решение review.

## Зачем

Сейчас решение по заявке считается только из LTV; пробег участвует лишь в
проверке допустимого диапазона (0..500 000 км, недопустимое значение
отклоняется до расчёта решения). Авто с очень большим пробегом может
получить approve только на основании хорошего LTV — высокому износу
авто не уделяется внимания в решении.

## Constraints

- Порог: 400 000 км — формулировка задачи из интервью.
- Граница «не больше 400 000 км» — включительная: ровно 400 000
  понижения не даёт, review — начиная с 400 001. Источник: формулировка
  задачи из интервью («не больше»); подтверждение риск-менеджментом —
  см. Open questions.
- Правило только понижает решение: approve при пробеге выше порога
  становится review; review остаётся review; reject остаётся reject
  (никогда не «повышается» до review) — ответ в интервью.
- Пробег — понижающий модификатор поверх решения по LTV, не независимый
  сигнал: LTV рассчитывается как сейчас, пробег в него не входит;
  сценарии ужесточения (например, высокий пробег в review-зоне LTV →
  reject) не вводятся — ответ в интервью.
- Правило применяется при расчёте решения по заявке везде, где этот
  расчёт используется, без разделения поведения между точками вызова —
  ответ в интервью.
- Значение порога — бизнес-число, берётся из конфигурации правил, в коде
  не хардкодится — конвенция проекта (AGENTS.md); существующие пороги
  (500 000 км на пробег, пороги LTV) не меняются — ответ в интервью.
- Пробег свыше 500 000 км по-прежнему отклоняется до расчёта решения,
  новое правило фактически работает в окне 400 001–500 000 км — код:
  backend/src/Domain/ApplicationValidator.php, backend/config/rules.php.
- Отсутствующее поле пробега по-прежнему отклоняется, пустая строка из
  формы по-прежнему трактуется как 0 — поведение не меняется; источник:
  код: backend/src/Domain/ApplicationValidator.php, frontend/app.js;
  подтверждение — см. Open questions.

## Open questions

1. Граница порога: подтвердить, что ровно 400 000 км остаётся без
   понижения (включительное «не больше»), а review — с 400 001. Статус:
   открыт — решает риск-менеджмент (AGENTS.md: пороги не выбираются
   агентом).
2. Подтвердить, что значение 400 000 км согласовано риск-менеджментом.
   Статус: открыт — решает риск-менеджмент.
3. Поведение при отсутствующем/пустом пробеге (отсутствие поля —
   отклонение, пустая строка — 0): подтвердить текущее поведение как
   правильное или изменить. Статус: открыт — решает риск-менеджмент.
4. Нужно ли ужесточение «высокий пробег в review-зоне LTV → reject».
   Статус: закрыт — ответ в интервью: нет, в этой задаче не вводится;
   любое ужесточение — отдельное решение риск-менеджмента.

## Не входит

- Подсказки и проверка «400 000 км» на форме заявки — ответ в интервью.
- Причина review в ответе API (вердикт остаётся без объяснений) —
   ответ в интервью.
- Изменение существующих порогов: 500 000 км на пробег, пороги LTV —
   ответ в интервью.
- Схема БД, хранение заявок, сиды — ответ в интервью.
- Попутное исправление расхождения докблока и кода по границе
  LTV «approve» — ответ в интервью.
