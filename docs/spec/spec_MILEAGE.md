# Spec MILEAGE: пробег авто не больше 400 000 км, иначе решение review

Задача: MILEAGE. Источник замысла и единственный источник объёма работ —
`docs/intent/intent_MILEAGE.md`. Здесь — что считается сделанным; как реализовывать —
`docs/plan/`, не здесь.

## Входит / не входит

### Входит

- Проверка пробега при расчёте решения по заявке: пробег больше 400 000 км
  понижает approve до review (REQ-MILEAGE-01…04).
- Порог 400 000 км как бизнес-число в конфигурации правил
  `backend/config/rules.php`, без хардкода в коде (REQ-MILEAGE-01).
- Применение правила во всех точках, где рассчитывается решение:
  POST /api/applications и POST /api/ltv, поведение одинаковое (REQ-MILEAGE-06).
- Сохранение без изменений (проверяется, не меняется): расчёт LTV и его пороги
  (REQ-MILEAGE-05, 08), валидация пробега 0..500 000 км (REQ-MILEAGE-07),
  поведение при отсутствующем и пустом пробеге (REQ-MILEAGE-09, 10).

### Не входит

Источник каждого пункта — ответ в интервью (intent, «Не входит»), если не указано иное.

- Подсказки и проверка «400 000 км» на форме заявки.
- Причина review в ответе API: вердикт остаётся без объяснений.
- Изменение существующих порогов: 500 000 км на пробег, пороги LTV (60 %, 85 %).
- Сценарии ужесточения, в т. ч. «высокий пробег в review-зоне LTV → reject»
  (Open question 4 из intent — закрыт: не вводится).
- Схема БД, хранение заявок, сиды.
- Попутное исправление расхождения докблока и кода по границе LTV «approve».

## Требования

**REQ-MILEAGE-01.** Порог понижения по пробегу — 400 000 км — хранится в
конфигурации правил (`backend/config/rules.php`) и читается кодом оттуда; число
400 000 в коде Domain/Http не хардкодится.
Источник: intent, Constraints (конвенция проекта — AGENTS.md); значение 400 000 км —
формулировка задачи из интервью, подтверждение риск-менеджментом — Open question 2
(перенесён, открыт).

**REQ-MILEAGE-02.** При пробеге не больше 400 000 км решение по заявке не
понижается: рассчитывается по действующим правилам LTV, как до задачи.
Источник: intent, Замысел и Constraints; включительная граница «не больше» —
формулировка интервью, подтверждение риск-менеджментом — Open question 1
(перенесён, открыт).

**REQ-MILEAGE-03.** При пробеге больше 400 000 км решение approve понижается
до review.
Источник: intent, Замысел — формулировка задачи из интервью.

**REQ-MILEAGE-04.** Правило понижает только approve: при пробеге больше
400 000 км решение review остаётся review, решение reject остаётся reject
(до review не «повышается»).
Источник: intent, Constraints — ответ в интервью.

**REQ-MILEAGE-05.** Пробег — понижающий модификатор поверх решения по LTV,
не независимый сигнал: значение LTV рассчитывается по действующей формуле
(запрошенная сумма / оценочная стоимость × 100 %) и от пробега не зависит.
Источник: intent, Constraints — ответ в интервью; формула —
`backend/src/Domain/LtvCalculator.php:25`.

**REQ-MILEAGE-06.** Правило применяется при каждом расчёте решения по заявке;
поведение в POST /api/applications и POST /api/ltv одинаковое.
Источник: intent, Constraints — ответ в интервью; точки расчёта —
`backend/src/Http/ApplicationController.php:28,59`.

**REQ-MILEAGE-07.** Валидация пробега не меняется: допустимый диапазон
0..500 000 км включительно, значения вне диапазона отклоняются до расчёта
решения; новое правило фактически работает в окне 400 001–500 000 км.
Источник: intent, Constraints; код — `backend/src/Domain/ApplicationValidator.php:43-46`,
порог 500 000 км — `backend/config/rules.php:23`.

**REQ-MILEAGE-08.** Пороги решения по LTV не меняются: approve_max = 60 %,
review_max = 85 %.
Источник: intent, Constraints и «Не входит» — ответ в интервью; значения —
`backend/config/rules.php:44-45`.

**REQ-MILEAGE-09.** Заявка без поля `mileage` отклоняется валидацией до расчёта
решения (HTTP 422, ошибка по полю `mileage`) — поведение не меняется.
Источник: intent, Constraints; код — `backend/src/Domain/ApplicationValidator.php:43`
(отсутствие поля → подставленное значение вне диапазона → ошибка валидации);
подтверждение риск-менеджментом — Open question 3 (перенесён, открыт).

**REQ-MILEAGE-10.** Пустая строка в поле пробега трактуется как 0 км — поведение
не меняется (форма: `Number('')` → 0; API: приведение к int).
Источник: intent, Constraints; код — `frontend/app.js:14`,
`backend/src/Domain/ApplicationValidator.php:43`; подтверждение риск-менеджментом —
Open question 3 (перенесён, открыт).

## Критерии приёмки

Тестовая заявка (общая для всех AC, если в AC не указано иное): VIN
`XTA21099998765432`, год = текущий − 4, срок 24 мес., оценочная стоимость
900 000 ₽; запрошенная сумма задаёт зону решения: 450 000 ₽ → LTV 50 % → approve,
675 000 ₽ → LTV 75 % → review, 855 000 ₽ → LTV 95 % → reject. Источники: примеры —
`tests/Unit/AssessmentServiceTest.php:36-43,47,57,66`; пороги зон —
`backend/config/rules.php:44-45`; формула LTV — `backend/src/Domain/LtvCalculator.php:25`.

**AC-MILEAGE-01 — REQ-MILEAGE-01. Порог читается из конфигурации.**
Given: в конфигурации правил порог понижения по пробегу — 100 000 км
(изменён только конфиг, код не меняется).
When: расчёт заявки с LTV 50 % и пробегом 200 000 км.
Then: decision = review.
(100 000 и 200 000 км — учебные значения для проверки конфигурируемости.)

**AC-MILEAGE-02 — REQ-MILEAGE-02. Сразу до порога.**
Given: заявка с LTV 50 %, пробег 399 999 км.
When: расчёт решения.
Then: decision = approve.

**AC-MILEAGE-03 — REQ-MILEAGE-02. Ровно на пороге.**
Given: заявка с LTV 50 %, пробег ровно 400 000 км.
When: расчёт решения.
Then: decision = approve — граница включительная, понижения нет.

**AC-MILEAGE-04 — REQ-MILEAGE-03. Сразу за порогом.**
Given: заявка с LTV 50 %, пробег 400 001 км.
When: расчёт решения.
Then: decision = review, approved_limit = 0
(лимит выдаётся только при approve — `backend/src/Domain/AssessmentService.php:39`).

**AC-MILEAGE-05 — REQ-MILEAGE-04. Review не ужесточается.**
Given: заявка с LTV 75 %, пробег 400 001 км.
When: расчёт решения.
Then: decision = review (не reject).

**AC-MILEAGE-06 — REQ-MILEAGE-04. Reject не смягчается.**
Given: заявка с LTV 95 %, пробег 400 001 км.
When: расчёт решения.
Then: decision = reject.

**AC-MILEAGE-07 — REQ-MILEAGE-05. Пробег не входит в LTV.**
Given: две заявки с LTV 50 % (сумма 450 000 ₽, стоимость 900 000 ₽),
различаются только пробегом: 96 000 км и 450 000 км.
When: расчёт обеих.
Then: `ltv` в обоих ответах = 50.0 (решения — approve и review, см. AC-MILEAGE-02,
AC-MILEAGE-04).
(96 000 км — `tests/Unit/AssessmentServiceTest.php:38`; 450 000 км — учебное
значение внутри окна 400 001–500 000 км.)

**AC-MILEAGE-08 — REQ-MILEAGE-06. Точка расчёта без сохранения.**
Given: заявка с LTV 50 %, пробег 450 000 км.
When: POST /api/ltv.
Then: HTTP 200, decision = review.

**AC-MILEAGE-09 — REQ-MILEAGE-06. Точка приёма заявки.**
Given: та же заявка (LTV 50 %, пробег 450 000 км).
When: POST /api/applications.
Then: HTTP 201, decision = review.
(HTTP-коды — `backend/src/Http/ApplicationController.php:50,64`.)

**AC-MILEAGE-10 — REQ-MILEAGE-07. Верх окна: ровно 500 000 км.**
Given: заявка с LTV 50 %, пробег ровно 500 000 км.
When: отправка заявки.
Then: валидация проходит, decision = review (500 000 км входит в диапазон
валидации и в окно правила).

**AC-MILEAGE-11 — REQ-MILEAGE-07. Сразу за окном.**
Given: заявка с пробегом 500 001 км.
When: отправка заявки.
Then: HTTP 422, в ответе ошибка по полю `mileage`, решение не рассчитывается
(422 на валидации — `backend/src/Http/ApplicationController.php:30,61`).

**AC-MILEAGE-12 — REQ-MILEAGE-08. Пороги LTV прежние.**
Given: заявка с пробегом 96 000 км (ниже порога понижения) и LTV 50 % / 75 % / 95 %.
When: расчёт решения.
Then: decision = approve / review / reject — как до задачи.
(Граничные LTV ровно 60 % и 85 % в этой задаче не проверяются: расхождение
докблока и кода по границе «approve» — вне задачи, см. «Не входит».)

**AC-MILEAGE-13 — REQ-MILEAGE-09. Поле mileage отсутствует.**
Given: заявка без поля `mileage`, остальные поля — как в тестовой заявке.
When: отправка заявки.
Then: HTTP 422, в `errors` есть ключ `mileage`, решение не рассчитывается.

**AC-MILEAGE-14 — REQ-MILEAGE-10. Пустая строка пробега.**
Given: заявка с LTV 50 %, поле `mileage` — пустая строка.
When: отправка заявки.
Then: валидация проходит, decision = approve (пустая строка трактуется как 0 км;
0 ≤ 400 000, понижения нет).

## Open questions из intent — статус в спеке

1. Граница порога: ровно 400 000 км — без понижения, review — с 400 001.
   **Перенесён**: остаётся открытым, решает риск-менеджмент (AGENTS.md: пороги не
   выбираются агентом). До подтверждения спека фиксирует включительную границу
   по формулировке интервью «не больше»: REQ-MILEAGE-02, AC-MILEAGE-03.
2. Значение 400 000 км согласовано риск-менеджментом.
   **Перенесён**: остаётся открытым, решает риск-менеджмент. До подтверждения
   значение из интервью зафиксировано в REQ-MILEAGE-01.
3. Поведение при отсутствующем/пустом пробеге (отсутствие поля — отклонение,
   пустая строка — 0): подтвердить или изменить.
   **Перенесён**: остаётся открытым, решает риск-менеджмент. До подтверждения
   зафиксировано текущее поведение как неизменное: REQ-MILEAGE-09, REQ-MILEAGE-10,
   AC-MILEAGE-13, AC-MILEAGE-14.
4. Ужесточение «высокий пробег в review-зоне LTV → reject».
   **Закрыт**: ответом в интервью — не вводится (REQ-MILEAGE-04, AC-MILEAGE-05);
   любое ужесточение — отдельное решение риск-менеджмента.

До закрытия вопросов 1–3 агент не меняет порог, границу и поведение при
пустом пробеге самостоятельно (AGENTS.md): при расхождении — остановиться
и спросить человека.
