# План: комментарий в backend/public/index.php

Запрос: «добавь комментарий в backend/public/index.php». Текст и назначение
комментария в запросе не заданы — ниже черновик, ждёт подтверждения заказчика.
ID задачи не дан, поэтому файл назван `plan_COMMENT-INDEX.md`; при появлении ID
файл переименовать по конвенции `plan_<ID>.md`.

## Файлы

- `backend/public/index.php` — единственный файл, который правит имплементатор:
  вставить один комментарий, больше ничего в файле не трогать.

Всё, чего нет в списке, при реализации трогать нельзя.

## Шаги

1. Вставить файловый докблок между `<?php` (строка 1) и
   `declare(strict_types=1);` (строка 3) — комментарии до `declare` допустимы.
2. Текст докблока (черновик, на подтверждение; это предмет правки, а не
   реализационный код):

   ```php
   /**
    * Точка входа HTTP API: подключает автозагрузчик и запускает приложение,
    * собранное AppFactory (бизнес-правила — backend/config/rules.php).
    */
   ```

   Факты в тексте — из docs/setup/code_map.md (AppFactory::create() собирает
   приложение и подключает backend/config/rules.php), ничего не додумано.
3. Больше изменений нет: `declare`, `use`, `require`,
   `AppFactory::create()->run()` остаются как есть.

## Тесты

- Новых тестов нет: комментарий не меняет поведение, тестировать нечего.
- `make lint` — синтаксис `backend/` после правки (php -l).
- `make test` — smoke-прогон без правки ожиданий: должен остаться зелёным;
  пороги, формулы и ожидания тестов не менять (AGENTS.md).

## Риски

- Докблок может устареть, если изменится сборка в `AppFactory` или подключение
  конфига: при таких правках обновлять комментарий вместе с кодом.
- Файл короткий (9 строк), но при правке легко зацепить лишнее — изменение
  строго одна вставка.
- Влияние на рантайм нулевое; LTV-пороги и формулы не затрагиваются.
